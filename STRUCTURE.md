# How This NixOS Configuration Is Organized

This file maps out every file in the config, how they link to each other,
and what each one is responsible for. Read this when you're lost or want
to know where to make a change.

---

## The Big Picture

```
flake.nix                          ← entry point, declares all external dependencies
└── hosts/victus/configuration.nix ← main system config for this specific machine
    ├── modules/audio.nix           ← PipeWire audio stack
    ├── modules/development.nix     ← all apps, dev tools, and local services
    ├── modules/nvidia.nix          ← NVIDIA + Intel Prime Sync
    ├── modules/flatpak.nix         ← Flatpak app management
    └── modules/desktop/nnn.nix    ← Niri + Noctalia + greetd (the desktop)

flake.nix (also wires up)
└── home-manager → users/harua/home.nix  ← per-user config (dotfiles, shell, Noctalia theme)
```

## File-by-File

### `flake.nix`
**Role:** The root of everything. A Nix Flake is like a `package.json` +
`yarn.lock` combined — it declares what external repos (inputs) this config
depends on, and pins their exact versions in `flake.lock`.

**What it does:**
- Declares all flake inputs (nixpkgs, home-manager, nix-flatpak, lobster, noctalia)
- Produces one output: `nixosConfigurations.victus` (the system build)
- Passes `inputs` down to all NixOS modules via `specialArgs`
- Passes `inputs` down to home-manager modules via `extraSpecialArgs`

**Key concept — `specialArgs`:**
Normally NixOS modules only receive `{ config, pkgs, lib, ... }`.
`specialArgs` injects extra values (like `inputs`) so modules can reference
other flakes (e.g. `inputs.noctalia.nixosModules.default` in nnn.nix).

**When to edit:** Adding a new flake input, changing nixpkgs channel,
or adding a new host machine.

---

### `flake.lock`
**Role:** Auto-generated lockfile. Like `package-lock.json` — records the
exact git commit hash of every input so builds are reproducible.

**Never edit by hand.** Update with:
```bash
nix flake update            # update all inputs
nix flake update nixpkgs    # update only nixpkgs
```

---

### `hosts/victus/configuration.nix`
**Role:** The top-level system configuration for the "victus" machine.
"Victus" is the hostname (`networking.hostName`).

**What it does:**
- Imports all modules (hardware, audio, nvidia, flatpak, desktop)
- Configures bootloader, networking, locale, keyboard
- Defines the `harua` user account and their groups
- Enables system-level programs (Firefox, Steam, Wireshark, Docker)
- Contains WiFi bug-fixes specific to this laptop's RTL8852BE-VT card

**When to edit:** System-level settings that are specific to this
particular machine — hostname, bootloader, user accounts, locale.

---

### `hosts/victus/hardware-configuration.nix`
**Role:** Auto-generated by `nixos-generate-config`. Contains filesystem
UUIDs, detected kernel modules, and partition mount points.

**Never edit by hand** (unless you know exactly what you're doing).
Regenerate with: `sudo nixos-generate-config --show-hardware-config`

---

### `modules/audio.nix`
**Role:** Audio stack. Configures PipeWire to replace PulseAudio.

**What it does:**
- Disables PulseAudio (required before enabling PipeWire)
- Enables rtkit for real-time audio scheduling (prevents crackling)
- Enables PipeWire with PulseAudio + ALSA + JACK compatibility layers
- 32-bit ALSA support is on so Steam/Wine games produce sound

**When to edit:** Audio-related issues, adding JACK support, changing
audio server configuration.

---

### `modules/development.nix`
**Role:** Everything you use day-to-day — apps, languages, CLI tools,
and local dev services.

**What it does:**
- `nixpkgs.config.allowUnfree = true` — allows proprietary packages
- `environment.systemPackages` — installs ~60 packages system-wide
- `services.n8n` — workflow automation server on port 5678
- `services.postgresql` — PostgreSQL 16 database (backend for n8n)
- `services.tor` — Tor SOCKS proxy at 127.0.0.1:9050
- References `inputs.lobster` to install lobster from its own flake

**When to edit:** Installing new apps, adding dev tools, configuring
local services (Postgres, n8n, etc.).

---

### `modules/nvidia.nix`
**Role:** NVIDIA RTX 4050 driver + Intel/NVIDIA PRIME Sync.

**What it does:**
- Enables `hardware.graphics` (OpenGL/Vulkan Mesa libraries, including 32-bit)
- Loads the NVIDIA driver via `services.xserver.videoDrivers`
- Enables kernel modesetting (required for Wayland)
- Uses the open-source NVIDIA kernel module (recommended for RTX 20xx+)
- Configures PRIME Sync: NVIDIA renders, Intel iGPU handles display output
- Enables GNOME Keyring for secret storage (used by VSCode, browsers, etc.)

**When to edit:** GPU-related issues, switching between PRIME Sync and
PRIME Offload, updating bus IDs after hardware changes.

---

### `modules/flatpak.nix`
**Role:** Declarative Flatpak app management via the nix-flatpak module.

**What it does:**
- Enables the Flatpak runtime
- Adds Flathub as a repository
- Installs Sober (unofficial Roblox client) as a Flatpak
- Adds Flatpak's share directories to XDG_DATA_DIRS so app icons appear

**When to edit:** Installing or removing Flatpak apps, adding more
Flatpak remotes (e.g. a self-hosted repo).

---

### `modules/desktop/nnn.nix`
**Role:** The NNN desktop stack — Niri + Noctalia + greetd.

**What it does:**
- Imports `inputs.noctalia.nixosModules.default` (from the noctalia flake)
- `programs.niri.enable = true` — registers the Niri Wayland session
- `programs.noctalia.enable = true` + `recommendedServices.enable = true`
  → starts Noctalia and enables its required system services
  (power-profiles-daemon, upower, bluetooth, etc.)
- Adds Noctalia's binary cache so it doesn't compile from source
- `services.greetd` — lightweight login manager with tuigreet UI
- NVIDIA Wayland environment variables (GBM_BACKEND, etc.)
- XDG portal for file picker integration
- Installs `foot` (terminal) and `wl-clipboard`

**When to edit:** Changing the desktop environment, display manager
settings, Wayland environment variables, or adding Wayland-specific services.

---

### `users/harua/home.nix`
**Role:** Per-user configuration for the `harua` account, managed by
Home Manager.

**What it does:**
- Imports `inputs.noctalia.homeModules.default` to get `programs.noctalia`
- Sets shell aliases (`ll`, `update`, `gs`)
- Configures git (name, email)
- Configures Noctalia theme (dark Catppuccin)
- Installs a few personal user packages (cowsay, lolcat, home-manager CLI)

**Receives `inputs` because:** `flake.nix` passes
`home-manager.extraSpecialArgs = { inherit inputs; }` which injects
`inputs` into this file's function arguments.

**When to edit:** Anything that is personal to the harua user —
dotfiles, shell config, per-user apps, Noctalia theme.

## How a Change Flows Through the System

```
You edit a .nix file
        ↓
sudo nixos-rebuild switch --flake /etc/nixos#victus
        ↓
Nix reads flake.nix → builds the system closure
        ↓
If it builds: atomically switches to the new generation
        ↓
New generation appears in systemd-boot menu as a rollback option
```

To roll back to the previous generation:
```bash
sudo nixos-rebuild switch --rollback
# or pick the previous entry in the systemd-boot menu at boot
```

## Module System: How Options Merge

NixOS modules don't call each other like functions. They each declare
options, and NixOS merges them all into one final config. This means:

- Two modules can both set `environment.systemPackages` — NixOS combines
  the lists (no conflict).
- Two modules setting the same scalar option (e.g. `networking.hostName`)
  would conflict — NixOS errors with "option already defined".
- `lib.mkOverride` / `lib.mkForce` / `lib.mkDefault` control priority
  when conflicts need resolving.

## Useful Commands

```bash
# Rebuild and switch to new config
sudo nixos-rebuild switch --flake /etc/nixos#victus

# Preview what would change without applying
sudo nixos-rebuild dry-activate --flake /etc/nixos#victus

# Build but don't switch (good for checking it compiles)
sudo nixos-rebuild build --flake /etc/nixos#victus

# Roll back to previous generation
sudo nixos-rebuild switch --rollback

# List all generations
sudo nix-env --list-generations --profile /nix/var/nix/profiles/system

# Apply home-manager config only (faster than full rebuild)
home-manager switch --flake /etc/nixos#harua

# Update all flake inputs (then rebuild)
nix flake update /etc/nixos

# Search for a package
nix search nixpkgs firefox

# Show what a package provides
nix-store -q --references $(which firefox)
```
